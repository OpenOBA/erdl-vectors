# 表达层向量 · 定位与验收标准（权威基线 · 修正版）

> 状态：权威基线（Henry 2026-09-05 定；本版修正了「语义 vs 字节」的错误对立）
> 日期：2026-09-05

## 一、一句话定位

> **ERDL 只保证「when → then」映射的一致。向量验的就是这个映射。**
>
> 具体：同一个 `when`（已成型的条件表达式），同一个规则包，经求值，得出的 `then`（结论）必须一致，且结论可哈希进审计链。

## 二、职责边界（ERDL 管什么、不管什么）

| 环节 | 谁负责 | ERDL 管不管 |
|---|---|---|
| 条款/法规 → 写成 when/then | 规则作者 + 质量门禁 | ❌ 不管 |
| **when 的求值（34 节点内核 + E 约束）** | **ERDL（确定性基座）** | ✅ **只保这个** |
| **when → then 映射（判定的确定性）** | **ERDL** | ✅ 只保这个 |
| 多模态输入、OCR/文本抽取 | 上游系统 / LLM | ❌ 不管 |
| 结论/过程/决策的生成 | LLM | ❌ 不管 |
| 结论进审计链、哈希 | ERDL（判定附带） | ✅ 附带 |

> 一句话：**「when/then 怎么写」是作者+门禁的事；「when 怎么算 → then 是什么」是 ERDL 的事。**

## 三、240 条向量在表达什么

| 类别 | 数量 | 验什么 |
|---|---|---|
| V-ENGINE node | 136 | 34 节点 × 4 场景（正常/边界/异常/空值）的求值确定 |
| V-ENGINE constraint | 52 | E1–E12 语义约束（E2 定点/E8 空数组/E9 时间/E11 空值…） |
| V-ENGINE simple | 30 | Simple 30 运算符编译到同一内核（28 compile + 2 modifier） |
| V-GLOSS | 16 | 树的自然语言投影 |
| V-PROJ | 6 | 三投影面归一到同一内核 |

**全部 240 条只验一件事：`when` 表达式的确定性求值，从而保证 `when → then` 映射一致。**
- 没有一个验「when/then 写对没有」（那是作者+门禁）
- 没有一个验「OCR 抽取/LLM 决策」（那是上游/LLM）

## 四、关于「语义一致」与「value 级一致」—— 之前措辞的修正

之前曾误将「语义一致」与「value 级一致（逐字节）」对立。**这是错的**：

- 代码里 `expected.value` 的比对，验的就是「when 求值产出的语义值一致」——它**就是**「语义一致」的工程化表达，不是「无关痛痒的字节」。
- 二者是**同一件事**，不是两回事。不存在「放松到决策级、放弃 value 级」这回事——因为 node 求值的 value，本就该逐值确定（这是确定性基座）。
- **「逐值」的单位是「语义值」，不是「字符串拼写」**：number 按 scale-14 定点数值比较（尾零不敏感，`"35"` ≡ `"35.0"`），string 按 NFC 归一化后字节比较，boolean 按真值比较。真正「不逐值」的是上游：OCR 抽文本、LLM 出决策——那些根本不在向量范围。

## 五、行业场景文档（scenario-*.md）的归属

`docs/scenario-{finance, healthcare, crossborder-ecommerce, law-accounting}.md` 里的「分叉点」（定点舍入、日期、法域阈值、空值）——

- **本质 = node 136（34 节点求值）+ constraint 39（E2/E9/E11）在真实业务规则下的具体化**
- 是「补强」现有 240 向量，不是「另起炉灶」的新验证维度
- 验收判据：与 node/constraint 向量相同（求值语义一致 + 可上审计链）
