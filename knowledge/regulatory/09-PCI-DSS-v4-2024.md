# PCI DSS v4.0.1 — Payment Card Industry Data Security Standard

## 基本信息

- **官方名称**: Payment Card Industry Data Security Standard: Requirements and Testing Procedures, v4.0.1
- **发布时间**: 2024年6月（v4.0.1 更新版），v4.0 于 2022年3月发布
- **强制生效**: 2024年3月31日（替代 v3.2.1）
- **发布机构**: PCI Security Standards Council (PCI SSC)，由 Visa、Mastercard、Amex、Discover、JCB 联合创立
- **官方页面**: https://www.pcisecuritystandards.org

## 核心内容

### 概述

PCI DSS 是支付卡行业的数据安全标准，适用于所有存储、处理或传输持卡人数据的实体。v4.0.1 是当前有效版本，包含12个核心要求，分为6个目标组。

### 12 项核心要求

| 目标 | 要求 | 说明 |
|------|------|------|
| **构建和维护安全网络** | 1. 安装和维护网络安全控制 | 防火墙、网络分段 |
| | 2. 对所有系统组件应用安全配置 | 硬化标准 |
| **保护账户数据** | 3. 保护存储的账户数据 | 加密、令牌化、截断 |
| | 4. 在开放公共网络上传输时保护持卡人数据 | TLS 加密 |
| **维护漏洞管理程序** | 5. 保护所有系统和网络免受恶意软件侵害 | 反恶意软件 |
| | 6. 开发和维护安全系统和软件 | 补丁管理、安全编码 |
| **实施强访问控制** | 7. 将对系统组件和持卡人数据的访问限制为仅那些有业务需要的人 | 最小权限 |
| | 8. 识别对系统组件的访问并验证访问者身份 | 身份验证 |
| | 9. 限制对持卡人数据的物理访问 | 物理安全 |
| **定期监控和测试网络** | **10. 记录并监控所有对系统组件和持卡人数据的访问** | **审计日志** |
| | 11. 定期测试安全系统和程序 | 渗透测试、漏洞扫描 |
| **维护信息安全政策** | 12. 支持信息安全的人员和政策 | 安全政策 |

### Requirement 10 — 日志和监控（核心条款详解）

#### 10.2 审计日志记录用户活动

**Defined Approach Requirement**: Implement automated audit trails for all system components to reconstruct the following events:

| 子条款 | 要求 |
|--------|------|
| **10.2.1.1** | 审计日志捕获所有个人用户对持卡人数据的访问 |
| **10.2.1.2** | 审计日志捕获拥有 root 或管理员权限的个人采取的所有操作 |
| **10.2.1.3** | 审计日志捕获对所有审计日志的访问 |
| **10.2.1.4** | 审计日志捕获所有无效的逻辑访问尝试 |
| **10.2.1.5** | 审计日志捕获对身份和认证凭证的所有更改（包括创建新账户、权限提升、管理账户变更） |
| **10.2.1.6** | 审计日志捕获审计日志的初始化、停止和暂停 |
| **10.2.1.7** | 审计日志捕获系统级对象的创建和删除 |

#### 10.2.2 审计日志条目内容

For each auditable event (from 10.2.1.1 through 10.2.1.7), record at least:

| 字段 | 说明 |
|------|------|
| **User identification** | 用户标识 |
| **Type of event** | 事件类型 |
| **Date and time** | 日期和时间 |
| **Success or failure indication** | 成功或失败指示 |
| **Origination of event** | 事件来源 |
| **Identity or name of affected data, system component, or resource** | 受影响数据、系统组件或资源的标识 |

#### 10.3 审计日志保护

> "Audit logs are protected from destruction and unauthorized modifications."

| 子条款 | 要求 |
|--------|------|
| **10.3.1** | 审计日志文件的读取访问限制为有工作需要的人 |
| **10.3.2** | 审计日志文件受到未经授权的修改保护 |
| **10.3.3** | 审计日志文件及时备份到集中的日志服务器或难以更改的媒体 |
| **10.3.4** | 使用文件完整性监控或变更检测机制确保现有日志数据不能被更改 |

#### 10.4 审计日志审查

> "Audit logs are reviewed to identify anomalies or suspicious activity."

- **日常审查**: 所有安全关键系统组件的审计日志必须至少每日审查
- **异常检测**: 识别异常或可疑活动
- **跟进**: 对已识别的异常进行调查和响应

#### 10.5 日志保留

| 要求 | 说明 |
|------|------|
| **最低保留期** | 至少12个月 |
| **即时可用** | 至少最近3个月的审计日志历史必须可立即分析 |

#### 10.6 时间同步

- 所有系统使用一致的时间设置
- 支持事件关联和取证分析

#### 10.7 审计日志故障

- 审计日志系统故障时的响应程序
- 确保日志连续性

## 与审计日志/决策记录/AI Agent 行为相关的要求

### 审计日志要求

**PCI DSS 是所有合规框架中对审计日志最具规定性的之一**:

- **7种必须记录的事件类型** (10.2.1.1-10.2.1.7)
- **6个必须包含的字段** (用户标识、事件类型、日期时间、成功/失败、来源、受影响资源)
- **日志完整性保护**: SHA-256 哈希链或 Merkle 树证明等密码学防篡改
- **文件完整性监控 (FIM)**: 确保现有日志数据不能被更改而不生成警报
- **集中日志管理**: 日志及时备份到集中服务器
- **每日审查**: 安全关键系统的日志至少每日审查

### 决策记录要求

- **访问控制决策**: 记录谁被授权访问持卡人数据环境 (CDE)
- **权限变更**: 记录所有权限提升和管理账户变更
- **系统变更**: 记录系统级对象的创建和删除
- **认证变更**: 记录身份和认证机制的所有更改

### AI Agent 行为相关

当 AI Agent 在持卡人数据环境 (CDE) 中运行时:

- **Agent 作为用户**: AI Agent 对持卡人数据的访问必须被记录为"个人用户访问"
- **Agent 权限**: AI Agent 的管理权限操作必须被完整记录
- **Agent 工具调用**: Agent 调用任何访问 CDE 的工具必须被审计
- **Agent 凭证**: Agent 使用的认证凭证的创建、变更和删除必须被记录
- **Agent 行为监控**: Agent 的异常行为模式需要被检测和警报

## 适用行业

- **所有处理支付卡的实体**:
  - 商户（线上和线下）
  - 收单银行
  - 发卡银行
  - 支付网关
  - 支付处理商
  - POS 系统提供商
  - 托管服务提供商
  - 任何存储、处理或传输持卡人数据的组织

## 处罚措施

| 违规类型 | 处罚 |
|----------|------|
| **支付品牌罚款** | $5,000 - $100,000/月 |
| **数据泄露后罚款** | $50 - $90/每张受影响卡 |
| **额外处罚** | 增加交易费用、终止商户账户 |
| **间接成本** | 诉讼费用、声誉损害、取证调查 |

### v4.0.1 相比 v4.0 的变化

- 澄清和更正测试程序
- 更新的指导说明
- 对多因素认证 (MFA) 要求的澄清
- 对自定义方法 (Customized Approach) 的改进说明
